## S — تأسيسية (مرة واحدة، وهي أولويتنا الآن)

### S1 — نظام الثيمات والتوكنز
> أنشئ نظام theming بـ CSS custom properties يدعم الوضع الفاتح والداكن، عبر تبديل class على العنصر الجذري بلا JavaScript عند التحميل الأول. استخدم تسمية دلالية للألوان (primitive → semantic → component). تأكد أن كل تباين نص/خلفية يحقق WCAG AA في الوضعين. **وادعم RTL بحيث لا يحتاج أي مكوّن إعادة كتابة** — استخدم الخصائص المنطقية (`margin-inline-start` بدل `margin-left`) و `bootstrap.rtl.css`. اجعل إضافة ثيم ثالث لاحقاً بلا refactor.

*نتيجة جيدة:* ملف tokens واحد + توثيق التسمية + عيّنة مكوّن واحد مطبَّق عليه للتحقق قبل التعميم.

### S2 — قالب الـ Layout بديلاً عن LeptonX
> نحن نستبدل قالب ABP LeptonX بـ Bootstrap 5 نقي. ابنِ Layout يعيد الوظائف التي سنفقدها: Navbar علوي، Sidebar قابل للطي تظهر عناصره حسب `PermissionService.getGrantedPolicy`، مبدّل لغة يستدعي ABP localization، breadcrumbs، ومنطقة محتوى بـ router-outlet مع lazy loading. استخدم صيغة Angular 19 الحديثة (`@if` / `@for`) لا `*ngIf` / `*ngFor`.

## A — قبل الإصدار

### A1 — تدقيق الوصولية
> راجع مكوّنات الواجهة مقابل Web Interface Guidelines. ركّز على: تباين 4.5:1، نصوص بديلة، التنقل بلوحة المفاتيح، aria-labels، مقاس اللمس 44×44 بحد أدنى، ووضوح حلقة التركيز. أخرج النتائج بصيغة `file:line`.

⚠️ **حرج بشكل خاص لشاشة أداء الامتحان** — مؤقّت تنازلي يجب أن يُعلَن لقارئ الشاشة عبر `aria-live`، وإلا فالشاشة غير قابلة للاستخدام لمرشح كفيف.

### A2 — احترام RTL
> افحص كل مكوّن في الوضع العربي: هل تنعكس الأيقونات الاتجاهية (أسهم، chevrons)؟ هل الأرقام والتواريخ والمؤقّتات تُعرض صحيحة؟ هل الجداول والنماذج تنعكس بلا كسر؟ اذكر كل مخالفة بالملف والسطر.

### A3 — الأداء والحجم
> دقّق الحزمة: استيرادات غير مستخدمة، CSS ميت، أصول غير مضغوطة، مكوّنات فوق الطية تُحمَّل متزامنة. رتّب حسب الأثر على زمن التحميل الأول ونفّذ أعلى خمسة مع شرح كل تغيير.

## B — بعد كل ميزة

### B1 — انحراف التصميم
> قارن المكوّنات الجديدة بنظام التصميم في S1. اذكر أي لون/مسافة/خط/نمط زر مكتوب مباشرة بدل استخدام التوكن.

### B2 — حالات الحافة المفقودة
> لكل شاشة جديدة: هل توجد حالة فارغة برسالة مفيدة (لا فراغ)؟ حالة تحميل؟ حالة خطأ قابلة للتعافي؟ تأكيد قبل الإجراءات المدمِّرة؟

## C — ربع سنوي

### C1 — احتكاك تجربة المستخدم
> راجع الواجهة والتنقل من منظور UX. حدّد نقاط الاحتكاك، الإشارات غير الواضحة، حالات التغذية الراجعة المفقودة، والتفاعلات المخالفة للتوقّع. لكل مشكلة: وصفها، سبب كونها مشكلة، وإصلاح محدد. رتّب حسب الأثر لا حسب سهولة التنفيذ.
>
> ركّز بالأخص على **رحلة المرشح**: يفتح رابطاً، يؤدي امتحاناً مؤقّتاً، لا فرصة ثانية. أي احتكاك هنا يكلّف مرشحاً حقيقياً درجته.

### C2 — تدقيق الطباعة
> راجع مقياس الخطوط والأوزان وارتفاع الأسطر وطول السطر. تحقق أن العربية والإنجليزية تعملان بنفس المقياس — الخط العربي يحتاج ارتفاع سطر أكبر عادة.

### C3 — تدقيق شامل بالمهارات
> شغّل `design-audit` على الواجهة كاملة، ثم `ui-ux-pro-max --stack angular` للتحقق من الأنماط الخاصة بـ Angular.
