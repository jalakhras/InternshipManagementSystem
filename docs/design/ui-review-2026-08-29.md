# UI/UX review — nine new screens

**Date:** 2026-08-29 · **Scope:** catalog, results (roster / detail / item analysis), groups,
settings, users, exam forms, exam structure, exam blueprint, assignment picker.
**Compared against:** `angular/src/styles/_tokens.scss`, `angular/src/styles/_base.scss`,
`angular/src/app/shared/ui/page-header.component.ts`, and the known-good
`angular/src/app/features/candidates/candidate-list.component.*`.

Ranked worst first. All paths relative to `angular/src/`.

---

## 1. Dead design tokens

**Almost clean.** One undefined custom property, four occurrences:

| File:line | Token |
|---|---|
| `app/features/catalog/catalog.component.scss:127` | `--astro-text-base` (`.group__title`) |
| `app/features/catalog/catalog.component.scss:219` | `--astro-text-base` (`.draft__title`) |
| `app/features/results/result-detail.component.scss:34` | `--astro-text-base` (`.stat__value--small`) |
| `app/features/exams/exam-forms.component.scss:155` | `--astro-text-base` (`.pane__title`) |

The scale is `2xs / xs / sm / md / lg / xl / 2xl / 3xl` (`styles/_tokens.scss:86-93`). There is no
`base`. **The failure is not "renders as nothing" — it is worse than that:** `font-size` is
inherited, so an invalid-at-computed-value-time declaration resets to the *inherited* size, not to
the rule it was overriding. `result-detail.component.scss:33` therefore does **not** fall back to
the `.stat__value` `xl`; it renders at the parent's 16px. The `exam-forms` `.pane__title` is an
`<h3>` that should be 22px and renders at 16px, silently flattening the heading. Fix:
`--astro-text-md`.

**Related, not dead but wrong:** the pattern `var(--astro-pass-600, var(--astro-brand-600))` appears
five times (`result-list.component.scss:49,187`, `result-detail.component.scss:43,124`,
`exam-forms.component.scss:91`). `--astro-pass-600` exists, so the fallback is unreachable — and if
it ever did fire it would paint a *pass* in the brand colour, which the token file forbids by name
(`_tokens.scss:16-18`). Delete the fallbacks; they express distrust of a token that is fine.

## 2. RTL correctness

**The SCSS is clean.** Zero physical properties across all eleven new stylesheets — no `left`,
`right`, `margin-left`, `padding-right`, `text-align: left|right`, or `translateX`. Every stylesheet
uses `inset-inline-*`, `margin-inline-*`, `text-align: start|end`. The new dialogs centre with
`place-items: center` on the scrim rather than the reference's `translate(-50%,-50%)` +
`:host-context([dir='rtl'])` override — that is genuinely better and should become the house
pattern.

**The bugs are all in the templates.**

### 2a. Every directional arrow points the wrong way (double-mirrored)

`styles/_base.scss:258-263` already mirrors `.bi-arrow-right`, `.bi-arrow-left`, `.bi-send` and
`.bi-box-arrow-right` globally in RTL, by selector, precisely so call sites do not have to remember.
The new screens then *hand-mirrored again* by choosing the physically opposite icon. Two mirrors
cancel: the arrow renders pointing the way it would in English.

| File:line | Icon | Purpose | Renders in Arabic |
|---|---|---|---|
| `app/features/results/result-detail.component.html:18` | `bi-arrow-right` | Back to results | points forward |
| `app/features/results/item-analysis.component.html:5` | `bi-arrow-right` | Back to results | points forward |
| `app/features/exams/exam-forms.component.html:6` | `bi-arrow-right` | Back to exam | points forward |
| `app/features/exams/exam-structure.component.html:5` | `bi-arrow-right` | Back to exam | points forward |
| `app/features/exams/exam-blueprint.component.html:6` | `bi-arrow-right` | Back to exam | points forward |
| `app/features/assignments/assignment-picker.component.html:37` | `bi-arrow-left` | Drill into exam | points backward |

The assignment picker is the clearest proof: `assignment-picker.component.scss:32-33` comments
"points the way the reader is going — mirrored with the page", and the code achieves the exact
opposite. Fix: use the LTR-natural icon (`bi-arrow-left` for back, `bi-arrow-right` for forward) and
let `_base.scss` mirror it, or use `bi-chevron-*` + `.astro-flip` as
`candidate-list.component.html:139,151` does. `.astro-flip` is used **zero** times in the nine
screens.

`bi-arrow-up` / `bi-arrow-down` (`exam-forms.component.html:159,167`) and `bi-arrow-left-right`
(`catalog.component.html:356`) are correct — vertical and symmetrical icons must not mirror, and do
not.

### 2b. Mixed number/punctuation strings are not bidi-isolated

The reference uses `.astro-numeric` / `.astro-ltr` (`styles/_base.scss:47-62`) eight times in one
file, for exactly this. The nine screens use them **five times in total, all on `<input>` elements**
— never on a read-only surface, which is where the rendering actually breaks. A neutral character
between two numbers inside an RTL paragraph takes the paragraph's direction and the operands swap.

| File:line | Renders as |
|---|---|
| `app/features/results/result-list.component.html:201` | pager `1 / 5` displays as `5 / 1` |
| `app/features/results/result-list.component.html:168` | score `12 / 20` displays as `20 / 12` |
| `app/features/results/result-detail.component.html:78,110` | topic and per-answer marks, same |
| `app/features/groups/group-list.component.html:154-158` | date range `2026/01/01 — 2026/06/01` reverses |
| `app/features/users/user-list.component.html:142` | email column, no `.astro-ltr` |

`user-list.component.html:142` is the sharpest one: `candidate-list.component.html:97` renders the
same data type as `class="muted astro-ltr"`. The adjacent screen, shipped a day later, dropped it.

## 3. Consistency

### 3a. The duplicated `.state` / `.spinner` block has drifted — and one copy is broken

Twelve files now carry a private copy of the same block, `@keyframes astro-spin` included.
`app/shared/ui/data-state.component.ts:16` exists to own this and **nothing imports it** — that is
the root cause. Canonical form: `candidate-list.component.scss:153-181`.

| File | Drift |
|---|---|
| `catalog/catalog.component.scss:303-318` | **`.spinner` is not defined at all.** Also rewritten: `padding` instead of `padding-block`, `--text-secondary` instead of `--text-muted`, no `i { font-size }`, no `state__text` max-width, no `.state--error`. |
| `results/item-analysis.component.scss:73-84` | no `__title`, no `--error`, `__text` 48ch not 44ch |
| `settings/settings.component.scss:92-101` | no `i { font-size }`, no `__title`, no `--error` |
| `exams/exam-blueprint.component.scss:105-117` | no `--error`, `__text` 52ch not 44ch |
| 7 others | byte-identical to canonical |

**The catalog copy is a live bug, not a style drift.** `.spinner` is not global (it is not in
`styles/`, not in Bootstrap, and every other component defines its own). So
`catalog.component.html:24` renders the word "loading" beside a zero-size invisible span, and
`catalog.component.html:444-446` — the vocabulary dialog's loading state, which is a spinner with no
text — renders **literally nothing**. The dialog appears empty until data arrives.

Also catalog-only: `catalog.component.scss` is the one file of the eleven with no
`:host { display: block; min-inline-size: 0 }`. Every other new screen opens with it, and
`candidate-list.component.scss:5-8` documents why. Catalog puts a two-column grid inside an
undefaulted inline host.

### 3b. Dialogs disagree with the reference and with each other

`candidate-list.component.html:259-275`: separate scrim element, click-scrim-to-dismiss,
`role="alertdialog"`, `aria-labelledby` pointing at the real title, Cancel first / destructive last.

`catalog.component.html:365-378`, `group-list.component.html:183-196` and
`user-list.component.html:172-185` all instead:

- put `role="dialog" aria-modal="true"` **on the scrim**, so the backdrop is the dialog;
- use `aria-label` rather than `aria-labelledby`, duplicating the `<h2>` that is right there;
- use `role="dialog"` for a destructive confirmation where `alertdialog` is the correct role;
- **put the destructive button first**, inverting the reference's order on every delete confirm;
- have no scrim-click dismiss and no Escape.

### 3c. Destructive actions: three screens do not confirm at all

Candidates, users and groups all confirm before deleting. These do not:

- `app/features/exams/exam-structure.component.ts:183` — `deleteSection` fires immediately
- `app/features/exams/exam-structure.component.ts:247` — `deleteGroup` (a passage) fires immediately
- `app/features/exams/exam-forms.component.ts:280-290` — `publish`, `retire` and `remove` all fire
  immediately from single text links (`exam-forms.component.html:100-113`)

Publishing a paper and retiring a live one are one mis-click apart, in the same row, styled
identically.

### 3d. `<td class="actions">` is turned into a flex container

`group-list.component.scss:108-112` and `user-list.component.scss:130-134` set `display: flex` on a
table cell. `candidate-list.component.scss:225-231` carries a comment explaining that this exact
change was already made once and "stacked four buttons on top of each row", along with its fix
(`inline-size: 1%; white-space: nowrap; text-align: end` on the `td`, flex on an inner span). Two
screens re-introduced it.

### 3e. Smaller drifts

- Numeric column class is `.num` in the reference, `.numeric` in all five new tables.
- Actions column header is empty (`group-list.component.html:133`, `user-list.component.html:134`)
  where the reference gives it a visually-hidden label (`candidate-list.component.html:82`).
- Errors arrive two ways: a full `.state--error` with a Retry button (catalog, results roster,
  groups, users, exam forms, exam structure, assignment picker) **or** a bare `alert alert-danger`
  strip with no retry (`item-analysis.component.html:23-25`, `exam-blueprint.component.html:20-22`,
  `settings.component.html:5-7`).
- Pager: the reference has chevrons and an `aria-label` of `::Pagination`;
  `result-list.component.html:193-209` has no icons and labels the nav `::Nav:Results`. Groups and
  users have no pager at all.
- `item-analysis.component.scss:31` uses `vertical-align: top` and omits `tbody tr:hover`; the other
  four tables use `middle` and have the hover.
- Busy state: the reference swaps the label to `::Working`; the new screens only `[disabled]` the
  button.
- Field hints: settings and blueprint are thorough; catalog has `field__hint` on one field of four
  (`catalog.component.html:106`), users on one of five, groups on one of six.

## 4. Touch and accessibility

- **No focus management anywhere.** Grep for `focus()`, `Escape`, `keydown`, `inert`, `autofocus`
  across all nine screens and the reference returns nothing. Six modal dialogs open without moving
  focus into them, without trapping it, without Escape, and without restoring focus on close.
  Keyboard focus stays on the page behind the scrim.
- **Colour is the only signal for "awaiting marking" vs "wrong"** on the marker's own screen.
  `result-detail.component.scss:124-126` distinguishes right / wrong / pending by
  `border-inline-start-color` alone. The comment claims "the marks say it too", but a pending answer
  and a wrong answer both read `0 / 2` (`result-detail.component.html:110`). Pending needs a word or
  an icon.
- **`role="status"` on a spinner with no text** announces nothing: `catalog.component.html:444`,
  `group-list.component.html:215`, `exam-forms.component.html:187`. Every other loading state pairs
  the spinner with `{{ t('::Loading') }}`.
- **Live regions inserted rather than updated.** `settings.component.html:156`,
  `catalog.component.html:439` and `exam-blueprint.component.html:142` create the
  `<span role="status">Saved</span>` only when `saved()` becomes true. A live region must exist in
  the DOM before its content changes; inserting one is unreliable across screen readers. Render it
  always and swap the text.
- **Reordering is silent.** `exam-forms.component.html:153-168` — Move up / Move down have correct
  `aria-label`s, but nothing announces the new position after the move.
- **Heading skip.** `exam-forms.component.html:139,185` uses `<h3>` with no `<h2>` between it and
  the page header's `<h1>` (`page-header.component.ts:16`). It is the only new screen that skips a
  level.
- **Targets under 44px** (`--astro-touch-min`, `styles/_tokens.scss:131`):
  `result-list.component.scss:96` `.segmented__option` is `2.25rem` (36px); the colour swatch at
  `settings.component.html:50` is `input[type=color]`, which `_base.scss:118-126` does not cover, so
  it takes Bootstrap's ~38px. Icon-only and text-link buttons are fine — they inherit the base 44×44
  floor because none of the `.link` / `.icon` rules override `min-block-size`.
- **Icon-only buttons are labelled correctly** everywhere they appear
  (`exam-forms.component.html:156,164,172`, `exam-blueprint.component.html:118`). Good.
- **Dark mode is broken for every text link.** `direction.service.ts:87-89` makes dark a real,
  user-selectable theme. Fifty-odd declarations across the eleven files reach past the semantic
  layer into primitives — exactly what `_tokens.scss:9-10` calls a bug — and primitives do not
  re-map by theme. On `--surface-raised` in dark:
  - `--astro-brand-700` (#16638c), the link colour at `catalog.component.scss:183`,
    `group-list.component.scss:118`, `user-list.component.scss:140`,
    `exam-forms.component.scss:113`, `exam-structure.component.scss:117` → **≈2.5:1**
  - `--astro-fail-600` (#b0342c), every `.link--danger` and every error icon → **≈2.7:1**

  Both fail 4.5:1 badly. `--accent`, `--status-fail-text` and `--status-pass-text` exist and do
  re-map. (The reference shares this habit in places, but the new screens make it the primary link
  colour on five screens.)
- **Semantic colour borrowed for non-outcomes**, which `_tokens.scss:16-18` reserves:
  `exam-forms.component.scss:91` paints a *published* paper in pass-green — published is not passed;
  `result-list.component.scss:51` paints *awaiting marking* in the brand blue when
  `--astro-pending-*` exists for precisely this and is unused across all nine screens.

## 5. Honest assessment

The results bullet covers three screens, so eleven lines below.

1. **Catalog** — No. Not shippable: the loading spinner does not exist, so the vocabulary dialog
   renders blank while it loads. Fix `.spinner` (and the missing `:host`) first.
2. **Exam structure** — No. Deleting a section or a passage is instant and irreversible with no
   confirmation, on a screen where a mis-click destroys an exam's shape. Add the confirm dialog
   first.
3. **Exam forms** — No. Publish, Retire and Delete are three identical unconfirmed text links in one
   row; make them confirm before anything else, then un-truncate the question text
   (`exam-forms.component.scss:191-198`) so a paper can actually be assembled.
4. **Users** — Almost. Add `.astro-ltr` to the email column (`user-list.component.html:142`) — the
   screen next door already does — and move `display: flex` off the `<td>`.
5. **Groups** — Almost. Same `<td>` flex bug plus a date range that reverses in Arabic; fix the
   `display: flex` on `group-list.component.scss:108` first, it is the one that visibly breaks rows.
6. **Results roster** — Almost. The pager reads `5 / 1` in Arabic; add `.astro-numeric` to
   `.pager__position` and the score cell first.
7. **Result detail** — Almost. A pending answer and a wrong answer are distinguished only by border
   colour and both show `0 / 2`; give pending a word first.
8. **Settings** — Almost. A failed load leaves an editable form full of blanks that Save will write
   (`settings.component.html:9-14` has no error branch); gate the form on `error()` first. (Bonus:
   the default brand colour offered to every new tenant is `#1f6feb` at line 53 — the generic SaaS
   blue `_tokens.scss:28-29` explicitly rejects.)
9. **Item analysis** — Yes, with a caveat. Give the error case the same `.state--error` and Retry as
   its siblings instead of a bare alert strip.
10. **Exam blueprint** — Yes. Cleanest of the nine: correct `.astro-numeric`, and the short-rule
    warning uses border, tint *and* words. Fix the back arrow.
11. **Assignment picker** — Yes. Only the chevron direction is wrong, and the fix is one word.

### If you fix five things, fix these

1. `.spinner` in `catalog.component.scss` — a screen currently renders an empty dialog.
2. Confirmation dialogs on `exam-structure.component.ts:183,247` and
   `exam-forms.component.ts:280-290`.
3. Delete the hand-mirrored arrows; let `_base.scss:258-263` do its job (6 lines, 6 files).
4. Move the link and danger colours off primitives onto `--accent` / `--status-fail-text`. Dark mode
   is shipping at 2.5:1.
5. Adopt `astro-data-state` (`app/shared/ui/data-state.component.ts`) — it already exists, nothing
   uses it, and twelve copies of its stylesheet have started to diverge.
